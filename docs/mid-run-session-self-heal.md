# Mid-Run Session Self-Heal — Reference Implementation

**Purpose of this document**: a portable spec of the session self-heal mechanism used in this repo (`PlaywrightFrameworkVantageDashboard`), written so it can be handed to Claude in a *different* Playwright + Cucumber BDD project that shares the same infra (Okta-authenticated storageState session, a CI job that runs long enough for the auth token to expire mid-suite) but currently lacks mid-run healing. It documents what exists, why each piece exists, and exactly what to build.

Source of truth in this repo: `src/utils/sessionGuard.ts`, wired into `support/hooks.ts`.

---

## 1. The problem this solves

A BDD/Playwright suite authenticates once (via Okta or similar), saves a `storageState` JSON, and reuses it across every scenario in the run. Two failure modes without this mechanism:

1. **Suite is long enough that the access token expires mid-run.** Every scenario after expiry starts failing with confusing redirect-loop / 401 errors, even though nothing in the app or test code is actually broken.
2. **Multiple role-suites run on the same self-hosted runner/workspace** (sequentially or concurrently) and each independently tries to detect+refresh the session — if two processes both decide to re-authenticate at once, they race on writing the same `storageSession.json` / `.env` files and can both hit the IdP simultaneously.

The fix has two distinct layers, deliberately scoped differently for local dev vs CI:

| Layer | Where it runs | Local behavior | CI behavior |
|---|---|---|---|
| **Pre-flight check** | Once, before the whole suite (`BeforeAll`) | Self-heals: blocks and runs the interactive/headed auth script | Hard-fails: throws immediately — CI is expected to arrive with a fresh session already generated by a prior pipeline step |
| **Mid-run self-heal** | Every scenario (`Before` hook) | **No-op** — local runs rely solely on the pre-flight check | Active: checks token freshness before every scenario; regenerates the session in-place once it drops under a safety buffer |

The asymmetry is intentional: a local developer's run is short and interactive (they can just re-run `npm run auth` if needed), so mid-run checks on every scenario would just be wasted work. CI runs are long, unattended, and must never fail purely because of a clock.

## 2. Prerequisites in the target project

Before implementing, confirm the target project has (or can add) equivalents of:

1. **A session file** that Playwright's `storageState` loads (e.g. `storageSession.json`), containing the IdP's token somewhere inspectable (JWT with an `exp` claim, or equivalent expiry field).
2. **Two auth scripts**:
   - A **local/interactive** one (headed browser, human can complete MFA/SSO) — e.g. `npm run auth`.
   - A **CI/headless** one (fully automated login via service-account credentials from secrets) — e.g. `npm run ci:auth`. This is the one mid-run self-heal will shell out to.
   - Both scripts must write the *same* session file path so the rest of the suite doesn't need to know which one ran.
3. **A Cucumber (or equivalent) hook structure** with a true "once before everything" hook (`BeforeAll`) and a "before every scenario" hook (`Before`).
4. **An `IS_CI` signal** (e.g. `!!process.env.CI`) to branch behavior.

If the target project's auth token is opaque (no `exp` claim you can decode offline), see §5.3 for the fallback.

## 3. Architecture

### 3.1 `checkSession()` — pure, offline, fast (<5ms)

Reads the session file, extracts the JWT, base64url-decodes the payload (no signature verification needed — this is a liveness check, not a security check), and compares `exp` against `now + EXPIRY_BUFFER_SECONDS`.

```ts
const EXPIRY_BUFFER_SECONDS = 300; // 5 min buffer against clock skew + in-flight scenario duration

export interface SessionStatus {
  valid: boolean;
  reason?: string;
  expiresInSeconds?: number;
}

export function checkSession(): SessionStatus {
  try {
    if (!fs.existsSync(SESSION_PATH)) {
      return { valid: false, reason: 'session file not found — run the local auth script first' };
    }
    const session = JSON.parse(fs.readFileSync(SESSION_PATH, 'utf-8'));

    // Adapt this extraction to however your IdP stores the token inside storageState.
    // This repo's shape: origins[].localStorage[] entry named 'okta-token-storage',
    // whose JSON value has .accessToken.accessToken as the JWT string.
    const tokenEntry = (session.origins ?? [])
      .flatMap((o: any) => o.localStorage ?? [])
      .find((e: any) => e.name === 'okta-token-storage');
    if (!tokenEntry) return { valid: false, reason: 'token key not found in session storage' };

    const jwt = JSON.parse(tokenEntry.value)?.accessToken?.accessToken as string | undefined;
    if (!jwt) return { valid: false, reason: 'JWT not found inside token entry' };

    const parts = jwt.split('.');
    if (parts.length !== 3) return { valid: false, reason: 'malformed JWT' };
    const payload = JSON.parse(Buffer.from(parts[1].replace(/-/g, '+').replace(/_/g, '/'), 'base64').toString('utf-8'));
    const exp = payload.exp as number | undefined;
    if (typeof exp !== 'number') return { valid: false, reason: 'JWT has no exp claim' };

    const expiresInSeconds = exp - Math.floor(Date.now() / 1000);
    if (expiresInSeconds <= EXPIRY_BUFFER_SECONDS) {
      return {
        valid: false,
        expiresInSeconds,
        reason: expiresInSeconds <= 0
          ? `Session expired ${Math.abs(expiresInSeconds)}s ago`
          : `Session expires in ${expiresInSeconds}s (under ${EXPIRY_BUFFER_SECONDS}s buffer)`,
      };
    }
    return { valid: true, expiresInSeconds };
  } catch (err) {
    return { valid: false, reason: `Session check threw: ${(err as Error).message}` };
  }
}
```

### 3.2 `ensureUiSession()` — one-time pre-flight (call from `BeforeAll`)

```ts
export function ensureUiSession(): void {
  const session = checkSession();
  if (session.valid) {
    console.log(`✓ Session valid — expires in ~${Math.floor(session.expiresInSeconds! / 60)}m`);
    return;
  }

  if (IS_CI) {
    // CI must arrive with a fresh session already generated by a dedicated
    // pipeline step. Failing here means THAT step is broken — don't paper
    // over it by re-authenticating a second time inside the test job.
    throw new Error(`CI session invalid: ${session.reason}. The auth job should have generated the session before this job runs.`);
  }

  console.warn(`⚠ Session invalid: ${session.reason}`);
  console.log('⟳ Running local auth script to refresh...');
  execSync('npm run auth', { stdio: 'inherit', cwd: path.resolve('.') });
  console.log('✓ Session refreshed. Continuing.');
}
```

### 3.3 `ensureFreshUiSession()` — mid-run self-heal (call from per-scenario `Before`)

This is the piece the target project is missing. Two things make it non-trivial:

1. It must be a **no-op locally** (`if (!IS_CI) return;`) — don't change local dev behavior.
2. It must handle **concurrent processes** safely if the target project ever runs multiple suites against the same runner/workspace. Even if it doesn't today, build the lock in — it's cheap insurance and this exact race has bitten this repo before.

```ts
const REAUTH_LOCK_PATH     = path.resolve('src/auth/.reauth.lock'); // must be .gitignore'd
const REAUTH_LOCK_STALE_MS = 150_000; // your ci:auth run's typical duration + margin
const REAUTH_WAIT_MAX_MS   = 180_000; // bound how long a waiting process blocks
const REAUTH_POLL_MS       = 2_000;

function sleepSync(ms: number): void {
  Atomics.wait(new Int32Array(new SharedArrayBuffer(4)), 0, 0, ms);
}

function isPidAlive(pid: number): boolean {
  try { process.kill(pid, 0); return true; }
  catch (err) { return (err as NodeJS.ErrnoException).code === 'EPERM'; }
}

/** Remove the lock if its owner is dead or it's older than the typical refresh duration. */
function stealStaleReauthLock(): void {
  try {
    const [pidStr, tsStr] = fs.readFileSync(REAUTH_LOCK_PATH, 'utf-8').split(':');
    const pid = Number(pidStr), ts = Number(tsStr);
    const abandoned = !Number.isFinite(ts) || Date.now() - ts > REAUTH_LOCK_STALE_MS
      || (Number.isFinite(pid) && !isPidAlive(pid));
    if (abandoned) fs.rmSync(REAUTH_LOCK_PATH, { force: true });
  } catch { /* lock vanished while inspecting — nothing to steal */ }
}

export function ensureFreshUiSession(): void {
  if (!IS_CI) return; // local relies solely on the BeforeAll pre-flight

  const session = checkSession();
  if (session.valid) return;

  console.warn(`⚠ CI session near/at expiry: ${session.reason}`);

  const startedWaiting = Date.now();
  for (;;) {
    let fd: number;
    try {
      fd = fs.openSync(REAUTH_LOCK_PATH, 'wx'); // atomic create-exclusive
    } catch (err) {
      if ((err as NodeJS.ErrnoException).code !== 'EEXIST') throw err;

      // Someone else is refreshing. Did they already finish?
      if (checkSession().valid) { console.log('✓ Session refreshed by another process.'); return; }

      stealStaleReauthLock();
      if (Date.now() - startedWaiting > REAUTH_WAIT_MAX_MS) {
        console.warn('⚠ Waited too long for a peer re-auth; attempting to acquire the lock.');
      }
      sleepSync(REAUTH_POLL_MS);
      continue;
    }

    try {
      fs.writeSync(fd, `${process.pid}:${Date.now()}`);
      fs.closeSync(fd);

      // Double-check: a peer may have refreshed between our check and acquiring the lock.
      if (checkSession().valid) { console.log('✓ Session already refreshed.'); return; }

      console.log('⟳ Regenerating session mid-run via CI auth script...');
      execSync('npm run ci:auth', { stdio: 'inherit', cwd: path.resolve('.') }); // your headless auth script
      console.log('✓ Session regenerated mid-run. Continuing.');
      return;
    } finally {
      fs.rmSync(REAUTH_LOCK_PATH, { force: true }); // always release, even on failure
    }
  }
}
```

**Why the loop instead of a simple retry-once**: the lock can be held by a peer for the full duration of a headless login (~40-60s in this repo). A naive "try once, give up" either fails a scenario unnecessarily or duplicates the login. The loop keeps polling until either (a) the session becomes valid because a peer finished, or (b) it successfully claims the lock itself (including by reclaiming an abandoned one), so it always terminates without deadlocking.

## 4. Wiring into hooks

```ts
// BeforeAll — once per suite process
BeforeAll({ timeout: 300_000 }, async function () {
  ensureUiSession(); // may block up to a few minutes locally if it must re-auth
  // ... browser launch, unchanged ...
});

// Before — once per scenario
Before({ tags: 'not @api', timeout: 120_000 }, async function (this: World) {
  ensureFreshUiSession(); // no-op locally; near-instant on CI unless refreshing
  // ... build context from the session file, unchanged ...
});
```

Notes:
- `BeforeAll`'s timeout must be generous enough to cover a full local re-auth run (this repo uses 300s).
- `ensureFreshUiSession()` must run **before** the scenario's browser context is built from the session file — otherwise a scenario could start with a context loaded from the stale file moments before it gets rewritten.
- If the target project has `@api`-only scenarios that skip the browser entirely, give them their own lightweight check against just the bearer/API token (see this repo's `ensureApiToken()`), not the full UI session check.

## 5. Adaptation checklist for the target project

1. **Locate the token inside the target's session file.** Different IdPs/SDKs store it differently (cookie vs localStorage vs sessionStorage; different key names). Only `checkSession()`'s extraction logic (the `flatMap`/`find` in §3.1) needs to change — everything else is generic.
2. **Confirm both a headless and headed auth script already exist**, or write the headless one first — `ensureFreshUiSession()` depends on being able to invoke it non-interactively via `execSync`.
3. **Pick `EXPIRY_BUFFER_SECONDS`.** 300s is this repo's value; size it to roughly cover your longest single scenario's duration plus margin, so a token doesn't expire *during* a scenario that started when the check said "valid."
4. **`.gitignore` the lock file** (`src/auth/.reauth.lock` or equivalent) alongside the existing session-file ignore entry — it's a runtime artifact, never commit it.
5. **Decide if the concurrency lock is needed.** If the target project's CI never runs multiple suites against the same workspace concurrently, the lock is still cheap to include (uncontended acquisition is a no-op-cost `fs.openSync`), so there's no reason to leave it out even if unused today.
6. **If the token is opaque** (no `exp` claim decodable offline — e.g. an opaque session cookie): you cannot pre-emptively detect expiry. Two fallback options: (a) treat a specific HTTP status/redirect during a scenario as the trigger to call the same re-auth-with-lock logic reactively, or (b) if the IdP exposes a lightweight introspection/`me` endpoint, poll that instead of decoding a JWT (adds a network call, so no longer <5ms — budget accordingly).
7. **Test both branches deliberately**: force an expired session file locally (should trigger the *pre-flight* self-heal in `BeforeAll`) and force one with `CI=true` set (should throw, not heal — confirms the intentional asymmetry). Then simulate near-expiry with `CI=true` to confirm `ensureFreshUiSession()` actually re-authenticates mid-run.

---

## 6. What NOT to copy as-is

- The exact `okta-token-storage` extraction shape — that's Okta/PKCE-specific to this app.
- The 300s/150s/180s/2s constants — tune to the target project's actual login duration and scenario length.
- `EXPIRY_BUFFER_SECONDS` reasoning assumes JWT `exp` is in Unix seconds — confirm the target IdP's claim format.
